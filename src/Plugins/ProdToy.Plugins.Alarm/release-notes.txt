Rich alarm window: markdown and html bodies, a folder per alarm, full editing over MCP
  - Three body kinds: text (the message, as before), markdown (rendered with tables, code blocks, images and links) and html (shown as a page, images included).
  - A markdown or html alarm keeps its content in its own folder, alarms/<id>/ in the plugin data folder: body.md or body.html with its images and css beside it. The folder is created with the alarm, copied by Duplicate and deleted with the alarm. Alarms saved before this release load unchanged as text alarms with no folder.
  - The alarm window is rebuilt: resizable (at least 420 x 320), remembers its size and position per screen, a header with the title, a priority colour strip and the schedule line ("Every day - 02:00 - 3rd firing"), a scrolling body, and a footer with Snooze, Open folder and Dismiss. It follows the host theme.
  - The edit dialog has a Body tab: choose the kind, write markdown or html in the editor or pick a file, open the folder, and preview the window before saving.
  - MCP: alarm_create and alarm_update take bodyKind, body (inline content) or bodyFile (a file copied in with the folders beside it and the relative files it references) and resources (extra files or folders to copy). alarm_update also takes every schedule field (schedule, time, date, days, dayOfMonth, intervalMinutes, inMinutes, startDate, endDate) plus note, notification, sound and fireAndForget; fields left out stay as they are.
  - MCP: new alarm_get (every field, the body, the body file and the folder) and alarm_preview (opens the window without firing it - no sound, no history row). alarm_list and alarm_history show the body kind.
  - The history remembers the body kind of each firing and keeps a copy of the body file when it is 2 MB or less.
